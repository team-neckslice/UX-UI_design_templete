# 데모 흐름(검토 반영본)

사업계획서 "UI/UX 데모 버전 개발 — 데모 흐름 계획" 표를 사업계획서 본문과 맞춰 검토하고 보완한 버전입니다.

> ※ 데모는 **2028년 관리형 단계의 목표 화면**입니다. 2027년 운영형은 팀이 직접 매칭하므로, 개발사 웹 의뢰와 집단 자동 제시는 관리형 기능입니다(사업계획서 2-1 단계표).

## 7단계 흐름

| 순서 | 화면 | 사용자 | 담을 내용 | 사업계획서 근거 |
|---|---|---|---|---|
| 01 | 테스터 프로필 등록 | 테스터 | 플레이한 게임·장르, 경험 수준, 환경, 참여 가능 일정, Steam 연동(선택), 근거 수준 표시 | 2-1 사용방법 1, 핵심기능 "프로필 축" |
| 02 | 의뢰 작성 | 개발사(기관 담당자) | 테스트 목적, 필수·선호 조건, 집단 구성, 인원, 일정, 보상 | 2-1 사용방법 2, 1-2 "10분 의뢰 서식" |
| 03 | 집단 제시·선택 | 개발사 | 조건 충족 근거와 미확인 항목, 해당 게임 미노출 확인, 집단별 인원, 승인·직접 선택·조정 요청 | 2-1 사용방법 3, 차별성 "정확한 매칭·매 회차 신규 공급" |
| 04 | 참여 제안·수락 | 테스터 | 테스트 내용, 보상, 일정, 동의 항목(NDA) | 2-1 사용방법 4 |
| 05 | 테스트 참여·피드백 제출 | 테스터 | 빌드 받기, 목적별 피드백 서식, 스크린샷·영상 첨부 | 2-1 사용방법 4 "목적에 맞는 서식으로 피드백 제출" |
| 06 | 진행 현황·결과 | 개발사 | 수락·시작·완료 현황, 대체 충원, 제출물 확인, 완료 확인·테스터 평가 | 2-1 사용방법 5, 차별성 "개발사 부담 최소화" |
| 07 | 완료·보상·이력 | 테스터 | 보상 지급, 받은 평가, 쌓인 참여 이력 | 2-1 사용방법 5·6 |

## 원래 표에서 바꾼 점

1. **05 테스트 참여·피드백 제출 화면 추가.** 원래 표에는 테스터가 피드백을 제출하는 화면이 없어, 06의 "제출물 확인"과 이어지지 않았습니다.
2. **03에 "해당 게임 미노출 확인" 추가.** 사업계획서의 핵심 문제인 "첫 이용자는 소모된다"를 화면에서 보여 주기 위해서입니다.
3. **06에 "완료 확인·테스터 평가" 추가.** 07에서 테스터가 받는 평가를 누가 하는지 흐름을 맞췄습니다.
4. **01에 "근거 수준 표시" 추가.** 차별성 "자기기입·연동·운영 확인 등 근거의 수준을 함께 보여준다"를 반영했습니다.
5. **02 사용자에 "기관 담당자" 병기.** 핵심 구매 고객인 기관·퍼블리셔를 데모에 드러내기 위해서입니다.

## 데모 시나리오(전 단계 공통)

| 항목 | 내용 |
|---|---|
| 게임 | 로그라이크 PC 게임(가상의 인디 팀) |
| 테스트 목적 | 튜토리얼 이해도(첫 경험 테스트) |
| 집단 구성 | 장르 초보 6명 + 장르 경험자 6명, 모두 해당 게임 첫 이용자 |
| 플레이 시간 | 60분 |
| 비용 | 개발사 부담 42만원 = 매칭료 24만원(12명 × 2만원) + 테스터 보상 18만원(12명 × 1.5만원) |

모든 단계 화면에 같은 게임 이름, 같은 테스터, 같은 숫자를 써서 영상이 한 이야기로 이어지게 합니다.

## 단계별 세부 화면(초안)

| 단계 | 세부 화면 |
|---|---|
| 01 | 회원가입·역할 선택 → 게임·장르 → 경험 수준 → 환경·일정 → Steam 연동 → 프로필 완료 |
| 02 | 테스트 목적 → 조건 → 집단 구성 → 일정·보상 → 확인·제출 |
| 03 | 집단 요약 → 테스터별 근거 → 직접 교체 → 승인 |
| 04 | 제안 알림 → 제안 상세 → 동의(NDA) → 수락 완료 |
| 05 | 빌드 받기 → 피드백 서식 → 스크린샷·영상 첨부 → 제출 완료 |
| 06 | 진행 대시보드 → 대체 충원 → 제출물 확인 → 완료 확인·평가 |
| 07 | 보상 지급 → 받은 평가 → 이력·프로필 갱신 |
